# 第 5 节 · Skill 就是 AI 的工艺卡

## 导读

最近，"AI Skill"这个词密集刷屏——Skill 管理工作台、UI Skill 合集、一句话克隆一个网站的 Skill……好几个开源项目接连冒头，热度肉眼可见地在涨。（这些是公开信息里的现象观察，不是本节要引用的数据。）

但绝大多数讨论，都停在"这个 Skill 好用""那个 Skill 是神器"的消费者层面。

这一节不讲安利。我自己造了十几个技能包，光内容写作这一块，就拆出了八个写作专项。所以我想站在生产者的角度，把一件事说透：

**Skill 不是更强的 prompt，是 AI 能力的一次资产化。**

## 一、为什么 prompt 不够用了

先说痛点。你大概率经历过这种时刻。

同一个需求，上周你写的 prompt 堪称神来之笔，AI 输出惊艳；这周换个项目再问，AI 像失忆了一样，输出平庸。你翻聊天记录找回那段"神 prompt"，复制粘贴，勉强能用——但你心里清楚，这只是把一次好运气，手动复刻了一遍。

再往后，来了个搭档或新人。你想把"怎么让 AI 写好技术方案"的经验传下去，于是写了篇文档。新人照着做，效果打折。因为文档记的是"要清晰、要分层、要有数据"，而真正决定质量的那几十条隐式判断——什么情况加类比、什么情况先给结论、什么情况必须上图——根本写不进文档，它们只活在你脑子里。

这就是 prompt 时代的三个硬伤：

- **一次性**：prompt 是消耗品，用完即弃，无法沉淀。
- **不可质检**：同一段 prompt，今天产出甲、明天产出乙，你没法给"产出质量"立标准。
- **不可传承**：经验锁在个人的手感里，换人就归零。

三个问题指向同一个病根。**真正的瓶颈，不是模型还不够强，而是能力交付缺一套工程化。**

说白了，这三个硬伤是同一件事的三个侧面：**你攒下的不是能力，是一次次碰运气的结果。** 运气没法存档，更没法交接。

## 二、Skill 是 AI 的工艺卡

工业界早就把这个问题解决过了。

一个老师傅凭手感车零件，良品率随心情浮动；但只要把"切削顺序、进给量、公差"写成一张**工艺卡**，钉在工位上，任何一个持证工人照着干，良品率立刻稳定下来。

老师傅的手感是 prompt，工艺卡就是 Skill。

一张工艺卡上，其实就那么几样东西：工序怎么排、参数怎么给、公差定多少、谁来检验。把这几样逐个对应到 Skill 上，它的骨架就清楚了：

| 工艺卡上写的 | Skill 里对应的 |
|-------------|----------------|
| 工序顺序 | 执行步骤：先干什么、后干什么 |
| 加工参数 | 约束条件：什么情况加类比、什么情况先给结论 |
| 公差范围 | 验收标准：产出什么样算合格、什么样算废品 |
| 检验规程 | 自检清单：交活之前，先自己过一遍 |

这个类比一旦立住，后面所有概念都顺了：

- prompt 是**手工作坊**，Skill 是**流水线工位**。
- 工艺卡有编号、有版本、有归档；Skill 也该有命名、有版本、有沉淀。
- **没有校验的 Skill，就像没有质检的流水线**——今天出良品，明天出废品，全凭运气。

所以请记住这层关系：

**prompt 解决"能不能做"，Skill 解决"能不能稳定地做、能不能复用地做、能不能传给别人做"。**

## 三、不是给 AI 戴枷锁，是给 AI 建立信用

有人抵触 Skill，觉得"写一堆规则约束 AI，是不是把它限死了"。这是典型的把限制看成了损失。

换个角度。你敢把一笔交易，交给一个"想到哪做到哪"的 AI 吗？不敢。你敢交给一个"只在白纸黑字写死的边界内行动、越界就立刻停下来问你"的 AI 吗？这个，你敢。

**限制不是枷锁，限制是信用。** 一个边界清晰的 Skill，是你敢把整件事交给它的前提。

我的内容审稿 Skill 之所以能放手跑，不是因为它"聪明"，而是因为它被写死了十条质量自检——标题命中公式没、类比密度够没、有没有判断句、有没有金句。它每产出一篇，都自带一份质检单。我批不批，看质检单，不看心情。

**没有自检的 Skill，就像厨师给自己的菜打分**——看着道道合格，真吃出问题才发现没人把关。

信用是一次一次攒起来的。你今天敢把一件事交给它，是因为昨天它交回来的东西，你抽检过、没出过事。**Skill 把"敢放手"从一种感觉，变成了一份可核对的历史。**

## 四、设计原则：冲着能力下限去设计

这点最反直觉，也最重要。

大多数人写 Skill，心里想的是"让 AI 发挥到上限"。错。你应该冲着**能力下限**去设计。

为什么？因为上限是惊喜，下限是交付。你给客户交一个东西，不能赌"今天 AI 状态好"。你得保证：哪怕 AI 今天状态最差，只要照着 Skill 走，产出的下限也是合格的。惊喜是加分项，合格才是承诺。

工业界的工艺卡就是这个逻辑——它不保证车出最完美的零件，它保证**最差的那一个零件，也在公差之内**。

落到操作上，意味着 Skill 里的每一步都必须可验证：

- 你让它"加类比"，就得规定类比的领域、密度、出现位置，能一眼数出来。
- 你让它"先给结论"，就得规定结论的句式，能对得上格式。
- 不能验证的要求，等于没写。

举个例子。你说"写得再犀利一点"——这句没法验证，AI 只能自己猜什么叫犀利。你说"每两到三段必须出现一个日常类比，全文至少三句判断句"——这就成了可以数、可以核的要求。**前者是许愿，后者是标准。**

**不可验证的指令，不是在用 AI，是在许愿。**

## 五、把 Skill 当资产，而不是脚本

这是生产者和消费者最大的分野。

消费者把 Skill 当脚本——能用就行，用完丢掉。生产者把 Skill 当资产——它会迭代、会复用、会进资产负债表。

我自己的体感：技能包这东西，第一个最贵，第二个开始摊薄。我花大力气把那套内容质量规则，从 27 篇阿里云开发者公众号文章里拆解出来，沉淀成一个可调用的 Skill（对，这一节本身，就是照那套规则写出来的）。之后每写一篇，都在复用这套规律，边际成本趋近于零。

**你写的每一个 Skill，都是在给公司攒工艺家底。**

要让 Skill 真正成为资产，四件事躲不掉：

1. **命名即地址**。Skill 叫什么、归哪个部门、住哪个目录，要像工位编号一样明确。散在桌面的脚本不叫资产，叫杂物。
2. **边界要窄**。一个 Skill 干一件事。想让它同时写方案、审方案、出图，它就三件事都干不好。窄边界，才有高下限。
3. **版本要管**。今天发现类比域该从"工业"换成"法律"，那是迭代，不是推翻。带上版本号，你能回溯每一次工艺改进。
4. **沉淀要成体系**。单个 Skill 是一张工艺卡，一组 Skill 才是一个工艺库。工艺库，才是护城河。

**一个 Skill 是一次经验，一柜子 Skill 才是一家公司。**

## 六、从 Prompt 到 Skill，是一次工业革命

回头看 prompt 时代，我其实是在用手工作坊的方式用 AI——每个人都是凭手感的老师傅，经验和运气，锁在个人脑子里。

Skill 做的事，是把这份手感**外化、固化、资产化**。它让 AI 能力，从"个人的灵感"变成"组织的工艺"。

这不是一次工具升级，是一次生产方式的跃迁。就像从作坊到工厂，产出的不只是更多，更是**可预期、可质检、可传承**。

作坊和工厂的差别，从来不在手艺高低，在手艺能不能被复制。作坊里最厉害的师傅一走，手艺就没了；工厂里最厉害的师傅走了，工艺卡还在。

所以别只盯着"哪个 Skill 又火了"。那都是别人写好的工艺卡。**真正值钱的，是你自己那张还没动笔的工艺卡。**

## 尾声

我正在把自己那十几个技能包的经验，一节一节拆出来。后面某一节，我会挑一个开源 Skill 做实测拆解——不吹不黑，看它的工艺卡设计到底硬不硬，校验有没有，边界画得清不清。

其实上一节那张七层图，已经把这一节的位置标好了。

因为 Skill 这件事，往上看、往下看，位置都很清楚。它是 AOSI 七层里的 L3——**工艺层**：工艺层之下，是工具层和基座层（模型、工具）；工艺层之上，是个体层与协作层（一个个 agent，以及它们怎么互相配合）。

**工艺层，就是把"散落的经验"变成"可复制的产能"的那一层。**

一个人的经验，只有先被写下来，才谈得上传下去；只有先被定成标准，才谈得上扩成一家公司。

你不需要今天就写完一张完美的工艺卡。写下第一张，哪怕它很糙——**粗糙但写下来的标准，胜过精致但只存在脑子里的手感。**

从下一个你反复做的动作开始写：你每次写文章之前，是不是都要想一遍"开头怎么钩人"？把这个想的过程写下来，就是你的第一张工艺卡。

工艺卡，就是那个起点。

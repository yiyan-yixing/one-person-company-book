# 第 3 节 · 一张路由表

第 1 节说到：给一堆乱七八糟的事起名字、分部门，混乱才有形状。这一节讲的是形状本身——那张路由表、那套文件夹、一天的节奏，还有几条谁都不能越过的红线。

这些东西长在同一个位置上：一家公司的**组织层**——路由、架构、红线。整本书会用一个七层模型把这一层画到图上（第 4 节会讲到），这一节先讲清楚它具体由什么构成。

## 一、整个系统里最重要的，是一张路由表

这件事里最重要的，不是哪个 agent 多聪明，也不是代码多漂亮——是一张表。

表长这样：

| 我说 | 谁来接 | 归到哪条线 |
|------|--------|-----------|
| 量化信号 / 策略 / 交易（模拟盘） | Alpha 研究员 agent 等 | 量化线 |
| 内容选题 / 写作 / 发布 | 主编 agent 等 | 内容线 |
| 模型训练 / 部署 | 开发 agent 等 | 模型线 |
| OneCode 开发 | 开发 agent | 软件线 |
| 学英语 | 英语辅导 agent | 学习线 |
| 辅导孩子数学 | 数学辅导 agent | 学习线 |
| 做饭 | 厨师 agent | 生活线 |
| 记账 / 报税 | 财务 agent | 财务线 |
| 合规 / 版权 | 法务 agent | 法务线 |
| 复盘 / 规划 | 总经理 agent | 总经办 |
| 夜间值班 | 夜班 agent | 全局 |

**规则很简单：我只跟一个入口说话——我雇的那个 agent 总经理。**

我说"今天公众号该推了"，它看一眼路由表，把任务转给主编 agent。我说"这个回测结果怎么看"，它转给回测员 agent。我说"晚上吃什么"，它转给厨师 agent。

听起来像一张企业组织架构图？没错。区别是我把它做进了文件系统里，由 AI 来执行调度。之前我直接跟 14 件事搏斗，现在我跟一个人说话——这个人也不是真人，是一个 agent 角色。

这跟软件架构里几个老模式是同一件事：**依赖注入**——调用方不关心具体实现，只声明自己需要什么；**中间件**——请求从一个入口进来，经过路由分发；**单一入口点**——外部所有交互都走同一个门面。路由表的本质，是把"你要什么"和"谁来干、在哪儿干"切开。

> **图 B-3-1**（待出）：路由表怎么把 14 件事分给 5 条业务线

**一个人最大的时间黑洞不是"做事慢"，是"切换成本"。** 你从写代码切到写公众号，光把上下文重新加载回来就要 5 到 10 分钟；14 件事来回切，一天光切换就浪费两个小时——而这还只是"加载"的账，第 1 节算过，真正把专注深度捡回来要二十多分钟。

路由表消灭的就是这个切换。我只管说"做什么"，不用管"谁来做"和"在哪做"。

它还顺手防住了另一种浪费：**闪念。** 你写代码的时候突然冒出一个选题灵感，以前你会直接切过去写两段，然后代码就忘了。现在的做法是——记到闪念笔记里，继续写代码。**闪念立刻记，不立刻做。** 路由表逼你聚焦。

## 二、文件系统就是你的公司大楼

你可能会问：这些 agent 在哪儿干活？它们没有聊天群，没有会议室——它们的办公室就是文件夹。

```
我的一人公司/
├── 主营
│   ├── 内容线        内容生产
│   └── 软件线        软件开发
├── 前沿
│   ├── 研究线        前沿研究
│   └── 量化线        量化投资（11 个 agent）
├── 基建
│   ├── 模型线        模型基建
│   └── 技能线        技能维护
├── 支撑
│   ├── 知识线        复盘与归档
│   ├── 财务线        记账报税
│   ├── 法务线        合规与版权
│   └── 总经办        治理与规划
└── 个人
    ├── 生活线        厨房与出行
    └── 学习线        英语与数学
```

这不是装饰。**每个文件夹就是一条业务线，每个 agent 在自己那条线里干活，不会串到别人的地盘。**

Alpha 研究员 agent 生成候选策略，写进量化线的策略池。主编 agent 写公众号，在内容线的流水线上流转。厨师 agent 规划菜单，落在生活线的厨房里。

**就像一栋写字楼：一楼交易大厅，二楼内容编辑部，三楼研发实验室，地下室财务室。** 你不需要告诉员工"去哪办公"——他们就在自己部门里，门牌号都写好了。

为什么要用文件夹，而不是数据库或者笔记软件？因为文件夹我能直接看、直接改、直接纳入版本管理。技术选型的最高标准不是"先进"，是"我能理解"。

## 三、上午打仗，下午磨刀，晚上复盘，夜里自治

路由表解决"谁做什么"，节奏解决"什么时候做什么"。

**上午，打仗。** 主营那两条线：内容线、软件线。A 股 9:30 开盘，信号要盯，公众号要推，客户要回——都是前线，不能拖。

**下午，磨刀。** 前沿和基建那几条线：研究、模型、技能、量化。上午的仗打完了，下午练兵。这些不紧急，但决定明天还能不能打。

**晚上，收束。** 知识线。记下今天做了什么、什么没做、什么做砸了。闪念也在这里落地——先记下来，不立刻做。

**夜间，自治。** 我去睡觉，agent 接着干：跑回测、训练模型、生成草稿、扫描市场异动——全是计算活，不需要我。早上七点半看一份晨报，一整夜的成果压缩成两分钟的阅读量。

**上午前线、下午后方，这个节奏是跟军队学的。** 你不会让前线士兵上午去练兵，也不会让后勤下午去冲锋。什么时候做什么事，是有结构的。

结构还逼出了另一条规则：**一天必做不超过三件事。** 路由表逼你一次只做一件，文件夹给这件事一个物理边界——浏览器标签页做不到，文件夹做到了。

> **图 B-3-3**（待出）：一天的节奏——上午打仗、下午磨刀、晚上复盘、夜里 agent 自己干活

真实的某一天是这样的。早上起来，夜里跑出来的东西在等我：一个 bug 修复、一份隔夜损益摘要、一篇内容草稿。我先看量化报告——模拟仓位在风控界限内，但有一个信号被回测员 agent 标了前视偏差。这说明质量检查在我睡觉的时候照样在工作。

午饭前我说"量化信号"：Alpha 研究员 agent 生成候选，因子工程师 agent 筛因子，回测员 agent 抡锤子做偏差诊断。九点之前三个信号入围，我读结果、选一个、说"执行"。**我的主动时间：15 分钟阅读，加一个决策。** 下午说"英语技能包"，开发 agent 装进学习线；说"复盘本周"，知识管理员 agent 已经归档好了。晚上六点辅导孩子，数学辅导 agent 见孩子不耐烦，自动换成画数轴——视觉方法比抽象规则管用。九点我说"夜班"，夜班 agent 接管，我合上电脑。

**那一天，我花在路由决策上 45 分钟。** 剩下的都是判断调用：选哪个信号、选哪条故事线、那笔账批不批。只有我能做这些决定，路由表处理了其余的一切。（平时大约 30 分钟，那天略多。）

## 四、37 个 agent，其实是三类人

可能你会问：37 个 agent，会不会太多了？

不多。因为它们只分三类，每一类管的领域完全不同。

**第一类，公司全局 18 个。** 总经理、产品经理、开发、测试、运维、架构师、法务、财务、数据分析师……不管你做什么业务，这些都是公司运转的基础角色。

**第二类，内容工厂 8 个。** 主编、编剧、设定师、写手、审稿、运营、商务、复盘官。从选题到写作到审稿到发布，一条龙。

**第三类，量化台 11 个。** 数据工程师、因子工程师、Alpha 研究员、回测员、风控、组合经理、交易员、合规、运维、报告员、量化研究员。从数据到因子到策略到回测到上线，也是一条龙。

**不是一个人要同时对付 37 个 agent。** 上午你在主营那两条线里，打交道的是内容工厂和开发；下午你在前沿和基建里，打交道的是研究员和那 11 个量化角色；晚上辅导孩子，打交道的是数学辅导 agent。跟路由表一样——你只管说做什么，系统帮你找到对的人。

## 五、人类红线：AI 提方案，人拍板

还有一条比"分工"更根本的原则：**有些事，AI 不能碰。**

五条红线，白纸黑字写死：

1. **（模拟盘）交易必须人批。** AI 可以算出"这个信号该买"，但按"买入"键的必须是我。
2. **发布必须人批。** AI 可以写草稿，但点"发布"的必须是我。
3. **法律决策必须人做。** AI 可以扫描合规风险，但判断"这个能不能做"的必须是我。
4. **（模拟盘）止损必须人扣。** AI 可以告警"回撤超限"，但执行止损的必须是我。
5. **战略方向必须人定。** AI 可以分析趋势，但选哪条路的必须是我。

**不是不信任 AI。是因为这些决策的后果，只有我能承担。**

AI 推荐了一个策略，模拟盘亏了 20%，它不会坐牢、不会被起诉、不会失眠。我会。

AI 写了一篇文章，发出去了，里面有个事实错误，它不会被起诉诽谤。我会。

AI 说"这个合同没问题"，签完发现知识产权纠纷，它不会赔钱。我会。

**红线不是限制 AI。红线是保护我。**

这跟 AI 安全里讲的"对齐"是同一个逻辑：不是 AI 不够强，是它的目标和人的真实意图之间有偏差。红线就是在操作层面做对齐——人显式地划出不可逾越的边界，而不是等 AI 自己学会"理解"人的价值观。

系统不替代你的判断。它把所有不是判断的事做掉，让你的判断更快。

## 六、这不是什么

说到这里，得泼几盆冷水。

**这不是 AGI。** 37 个 agent 不是 37 个通用智能体，是 37 个专家系统。厨师 agent 只会做饭，你让它写代码它写不了；回测员 agent 只会审计信号，你让它规划选题它也规划不了。专家系统不好听，但**窄范围是唯一让这东西工作的方式。**

**这不是完全自治。** AI 可以生成方案、执行计算、扫描风险，但最终决策是人做的。夜班 agent 跑了 10 个小时的活，产出压缩成一份晨报，然后等我醒来审批。

**这不是甩手掌柜。** 你不能搭完系统就去度假。系统只是把你从"一个人干 14 件事"，变成"一个人管 14 个 agent 干 14 件事"——还是要管，只是管的成本低得多。以前什么都自己干，我每天散乱地花掉 3 个小时；现在花在路由和判断上大约 30 分钟。少了，但不是零。

**什么会失败：** 模糊指令路由不到任何东西；角色重叠会让 agent 打架；没有红线，让 Alpha 研究员 agent 不经批准就去下单，你会学到风控为什么存在——学费很贵。

说到底，这是一个杠杆系统。以前你是一个人扛 14 块砖，现在有 14 个 agent 帮你扛，你只管说"这块搬哪儿"。

## 七、起步三步

如果你想试试这套东西，不需要一口气搭 37 个 agent。三步就够了。

**第一步：写你的路由表。** 拿一张纸，左边写"我每天在做什么"，右边写"这事该谁管"。

| 我在做的事 | 该谁管 | 住在哪 |
|-----------|--------|--------|
| 写代码做产品 | 开发 agent | 软件线 |
| 运营公众号 | 主编 agent | 内容线 |
| 量化交易（模拟盘） | Alpha 研究员 agent | 量化线 |
| 辅导孩子 | 数学辅导 agent | 学习线 |
| 做饭 | 厨师 agent | 生活线 |
| 记账 | 财务 agent | 财务线 |

写完你会发现：原来你每天干的不是一个"工作"，是六份工作。**路由表的第一价值不是自动化，是让你看见真相。**

你是独立开发者，你的路由表可能是：写代码→开发、测试→测试、部署→运维。你是自媒体人：选题→主编、起草→写手、发布→运营。你是量化交易者：研究→研究员、回测→回测员、风控→风控。**部门不同，模式相同。**

**第二步：针对最大痛点，创建一个 agent。** 不要贪多。你每天最痛的是哪件事？写公众号总是拖？创建主编 agent。回测总是来不及看？创建回测员 agent。做饭总想不出吃什么？创建厨师 agent。

**一个就够了。** 一个 agent 解决问题之后，你的信心会上来，自然会想加第二个。我是先搭了一个 Alpha 研究员 agent，量化台其余 10 个角色是从它长出来的。

建 agent 的关键：范围要窄、输出格式要明确、要有专门的目录。让它产出你能验证的东西——产出垃圾，你立刻知道该改指令；产出模糊，你永远不知道它在不在工作。

**第三步：建目录结构。** 不需要照搬我的。但你要给每条业务线一个"家"。

```
我的一人公司/
├── 赚钱的事      内容线 + 软件线
├── 升级的事      研究线 + 量化线
├── 记录的事      知识线
└── 生活的事      生活线
```

四个文件夹就行。agent 在各自的文件夹里干活，不串门，不冲突。

空文件夹不是没用——**空文件夹是一个承诺：这类工作住在这里。** 等 agent 填满它们的时候，结构已经在了。

## 尾声

三步做完，你就有一个"有名字、有归属、有流程"的一人公司了。混乱还在，但有了形状。有了形状的东西，就可以一点一点自动化。

给部门命名。画路由表。给每个角色一个目录。让 agent 做它们职责范围内的事，把判断调用留给自己。

从一个路由规则开始。一个 agent。一个目录。

够了。

至于 AI 之间怎么互相质疑、怎么把质量吵出来，那是后面单独一节的事。

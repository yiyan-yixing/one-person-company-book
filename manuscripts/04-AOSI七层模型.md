# 第 4 节 · AOSI 七层模型：把 AI 公司拆成 7 层

## 导读

所有人都在炫：我这个 agent 多能干，我这个 skill 多聪明，我这叫"AI 公司"。

但**少有人画过整张图**。

直到有一天你换了个更强的模型，整个系统跟着崩了——你才发现，缺的根本不是更强的 AI，是一张地图。

这张地图，网络界近半个世纪前就画好了，叫 OSI 七层模型。我把它借过来，给 AI 组织也画了一张，叫 **AOSI**——AOSI 系作者定义，指 Agent OSI（Agent 版开放系统互连参考模型），与网传 AI Open Systems Interconnection 同名项目无关。

而这七层，从下到上，每一层都重要——缺了哪层，系统就在哪一环崩。

---

## 一、先说清楚，为什么"分层"是刚需

很多人觉得"分层"是学院派的事，离实战远。恰恰相反，分层是为了解决实战里最疼的那个问题。

你一定经历过这种崩溃时刻：跑得好好的 agent，今天换个底座模型，整个行为就变形了；好不容易搭好的内容流水线，想加一道审稿，发现牵一发动全身，越改越乱。

根因只有一个：**你的系统里，层和层之间没有边界。** 模型和流程缠在一起，工具和角色缠在一起，谁也换不动谁。这不是某个环节没做好，是整个系统没有"分层"。

分层解决的就是这件事——**让每一层只干一件事，层和层之间留出干净的接口。** 这样你换掉任何一层，其他层都不受连累。

其实你已经会分层了，只是没意识到。我的一人公司里有一份核心配置文件，核心是一张"路由表"：我说"量化信号"就路由给因子工程师 agent，说"写内容"就路由给主编 agent。这张路由表的本质，就是在做分层——把"谁来干"和"怎么干"切开。

**分层不是为了好看，是为了让你能换掉任何一层，而不拖垮其他六层。**

## 二、AOSI 七层全图

OSI 从下到上七层：物理、链路、网络、传输、会话、表示、应用——再往上，是"人"。AOSI 照搬这套骨架，自下而上也是七层：

```
        ╔══════════════════════════════════════════════╗
   L7   ║  意图层   Mission      为什么做 · 创造什么价值  ║  ← 应用层之上 = 人
        ╠══════════════════════════════════════════════╣
   L6   ║  组织层   Org          路由 · 架构 · 红线 · 文化 ║  ← 应用层
        ╠══════════════════════════════════════════════╣
   L5   ║  协作层   Team         分工 · 交接 · 对抗审查    ║  ← 会话层
        ╠══════════════════════════════════════════════╣
   L4   ║  个体层   Agent        独立可靠交付一个任务      ║  ← 传输层 (TCP)
        ╠══════════════════════════════════════════════╣
   L3   ║  工艺层   Skill        一类活儿该怎么干          ║  ← 网络层
        ╠══════════════════════════════════════════════╣
   L2   ║  工具层   Tool         MCP · 函数调用            ║  ← 链路层
        ╠══════════════════════════════════════════════╣
   L1   ║  基座层   Foundation   Model · Data · Compute   ║  ← 物理层
        ╚══════════════════════════════════════════════╝
              物质（智能的底座）              意图（人定方向）
```

> **图 B-4-1**（待出）：AOSI 七层总纲图——最底下是物质（显卡、模型参数、数据），最顶上站着人，中间七层一样重要、谁也不比谁高

逐层解释，每层四个要素：**职责 / OSI 对应 / 我的一人公司里它长啥样 / 这层没做好会怎样**。

| 层 | 职责 | OSI 对应 | 我的现实 | 失败模式 |
|----|------|---------|---------|---------|
| **L7 意图层** | 为什么做、创造什么价值 | 应用层之上＝用户 | CEO 定方向、选题 | 没使命＝空转 |
| **L6 组织层** | 路由 / 架构 / 红线 / 文化 | 应用层 | 一人公司系统（路由表+目录） | 没路由＝一个人累瘫 |
| **L5 协作层** | 多 agent 分工、交接、对抗 | 会话层 | 内容工厂 / 量化 desk | 没对抗＝粉丝后援会 |
| **L4 个体层** | 独立可靠完成一个任务 | 传输层(TCP) | 开发 agent / 因子工程师 agent | 没边界＝到处闯祸 |
| **L3 工艺层** | 一类活儿怎么干 | 网络层 | 自研技能包 | 不可复用＝一次性 |
| **L2 工具层** | MCP / 函数调用 | 链路层 | tools / MCP 接口 | — |
| **L1 基座层** | 模型 + 数据 + 算力 | 物理层 | Qwen / GLM / 本地算力 | — |

（一个诚实的说明：OSI 和 TCP/IP 本身也不是逐层死扣的——真正的网络协议都没法严丝合缝塞进 OSI。所以这张图借鉴的是 OSI 的**分层精神**，不是教条。三层映射特别硬，下面单说。）

## 三、三个最硬的映射

分层模型怕的不是层多，是类比牵强。AOSI 里有三处映射是真成立的，值得单独拎出来。

**第一个，L4 Agent ↔ 传输层（TCP）。**
传输层管的是"端到端可靠交付"——保证一份数据，从这一头完整、不丢、不乱地送到那一头。Agent 管的是"一个任务，可靠交付"。两者都讲究同一件事：**有边界、可重试、有确认**。一个好 agent 就像一个好 TCP 连接——任务没干完不撒手，干砸了知道重来，干完了给你回执。这是七层里最贴的类比。

**第二个，L5 Team ↔ 会话层。**
OSI 七层里，会话层是最容易被一笔带过、却最难做的一层——它管"多端怎么建立会话、怎么维持、怎么结束、谁先谁后"。这跟 team 层一模一样。一个 agent 单干，再强也是单口相声；可一旦多个 agent 要协作，问题立刻从"能力"变成"协议"：谁先说、谁接话、产出交给谁、意见不合怎么办。**会话层难，恰恰是因为它要从"一个"变成"一群"。**

**第三个，L7 Mission ↔ "用户层"。**
这是最妙的收尾。OSI 模型到第七层（应用层）就停了——**再往上，是人**（用网络的那个用户）。AOSI 也一样，到 L7 意图层，再往上，是人（定方向的 CEO）。**两个模型，都"到人为止"。** 因为你没法给"人为什么做这件事"再编一层协议——那是源头，不是技术。

记住这三个映射，整套图就活了：**Agent 是连接，Team 是会话，Mission 之上是人。**

## 四、今天的 AI 圈，火力分布在哪

看看现在的 AI 圈，各层的火力分布很不均：

- **L1–L3（基座 / 工具 / 工艺）**：技术圈在死磕。卷模型、卷工具、卷 skill 模板。红海。
- **L4 个体层**：做出一个能干的 agent 就发推了——多数人停在这一层，没往下走。
- **L5 协作层**：框架一大把，把这层当工程建的极少。
- **L6 组织层**：叙事圈在卷。"我搭了个 AI 公司，全自动"的故事很热闹，但不少停在演示级——有壳没魂，演示好看，一上量就散。
- **L7 意图层**：被跳过最多的一层——想清楚"为什么做"，比"怎么干"更难。

火力不均，是因为每一层的难度不一样：让一个 agent 看起来很能干（L4），是表演；让多个 agent 真正协作（L5），是工程——后者比前者难上一个量级。但火力不均，不代表哪一层更重要：**缺了哪一层，系统就在哪一环崩**。L1-L3 不卷就没地基，L4 没边界到处闯祸，L5 不交接就丢上下文，L6 没路由上量就乱，L7 没使命就空转。

这也是我敢说"我跑着 37 个 agent"而不是"我跑着 37 个脚本"的原因——不是哪一层起了决定性作用，是七层一起，把脚本组织成了队伍。

## 五、分层真正的力量：解耦

回到开头那张 OSI 图。它最伟大的地方，从来不是"刚好分成七层"，而是**分层带来的解耦**。

想想网络史：物理层从铜线换成光纤、换成无线，应用层的网页一行代码都不用改。这就是分层给的底气——底层翻天覆地，上层岿然不动。

AI 组织需要的就是这份底气。在我的系统里：

- **L1 换底座**：Qwen 换成 GLM、再换成更强的模型，L4 的 agent 一行都不用改。
- **L3 迭代工艺**：技能包发现类比域该调整，那是工艺升级，不推翻 L6 的组织架构。
- **L5 加一道对抗**：给量化 desk 加个回测挑刺的 agent，不牵动内容工厂。

**每层都能独立演进，前提是层和层之间有干净的边界。**

这恰恰是绝大多数人做不到的——他们的 AI 系统，是"一坨"，模型、工具、提示词、流程全焊在一起，动一个地方就常常崩。那不叫系统，那叫**精致的脆弱**。

分层的反义词不是"不分层"，是"焊死"。**分层让你拥有了改的权利，焊死让你只剩祈祷。**

## 六、这张图，一头是物质，一头是人

最后说一个你可能没注意的对称性。

看 AOSI 全图：最底层 L1 是**物质**（显卡、模型参数、数据），最顶层 L7 是**意图**（人为什么做这件事）。

整张图的意思是：**人，站在最上面，用一摞机器，把底下的智能物质，组织成顶上的价值意图。**

这不是巧合。你去把人类组织学翻开看——最底层是"职业技能"，往上是"员工"，再上是"班组协作"，最上是"公司战略与使命"。一个工人凭手艺干活（L1-L4），一群工人靠分工和质检把活做大（L5），公司用组织架构和文化把人聚成共同体（L6），最顶上是"我们这家公司为什么存在"（L7）。

**AOSI 七层，在很大程度上，是人类组织的镜像。**

这就是我最想讲的一句话：

> **AI 组织学的最佳教材，不是 AI 论文，是人类管理学。** 那些分工、对抗、边界、使命的难题，组织行为学几十年前就替你趟过一遍了。你不必在 AI 里重新发明管理，你只需要把人类攒下的管理智慧，迁移到这群新员工身上。

这也是为什么协作层（L5）极少被当成工程来建——AI 圈在拿"提示词工程"的思路硬啃协作问题，而协作本质是个管理学问题，得用管理学的解法：明确分工、建立交接标准、引入对抗审查、画清红线。

## 尾声

1970 年代，网络界画了一张七层地图，叫 OSI。后来真正联网跑的协议是 TCP/IP，但"分层"这套思想，成了整个网络世界的通用语言——OSI 留下的最大遗产，不是某个协议，是**给混乱分层的方法**。

今天 AI 也走到了这一步。每个人都在喊 agent、喊 skill、喊 AI 公司，但少有人愿意停下来，先把那张组织架构图画出来。

AOSI 干的就是这件事。它要让人从"一个 prompt、一个人"的手工作坊，长成"一家公司"。

你不需要一下子搭满七层。**从一张路由表开始**（那是 L6），**给一个 agent 划清边界**（那是 L4），**再让两个 agent 学会互相挑刺**（那是 L5）。三层搭起来，你就从一个"用 AI 的人"，变成了一个"组织 AI 的人"。

剩下的四层，不会自己长出来。

——除非你从第一天起就为它们留好接口。没有刻意的架构设计，剩下的四层长出来的不是协作，是一团乱麻。AOSI 要防的，正是这种"自己长出来"的乱麻。

# 第 10 节 · 内容工厂：从选题到发布

这本书前面十几节引到的那些文章——本地模型实测、量化台复盘、一人公司怎么开——不是我一篇篇坐下来写出来的。它们是**从一条流水线上流出来的**。

这一节讲三件事：这条线怎么搭、它真的跑通时是什么样、以及它卡在哪一步。第三件最重要——**一条流水线最值钱的部分，常常不是它能跑多快，是它在哪里跑不动。**

## 一、把"写文章"变成一条流水线

写作这事，原来在我这儿是个黑箱：想写就写，不想写就拖，写完随手一发。黑箱没法管理——你只能等它。

要把它变成能管的东西，第一步是把黑箱拆成工位。我给它定了五个阶段：

**待定 → 写作 → 审 → 就绪 → 已发布。**

一个选题进来，先落"待定"；决定写了，挪到"写作"；稿子出来，进"审"；审过了，进"就绪"；发出去了，进"已发布"。每一次挪动是一行命令，状态文件里就多一条时间戳。

这五个词没什么技术含量。**有含量的是每个阶段附带的两条规矩。**

**第一条：每一环必须把产出落成文件。** 写完不是"写完了"，是正文文件躺在任务目录里、字数是数得出来的、状态回写了"已进审"。审完不是"审完了"，是审稿结论落成一个文件——过还是不过，不过卡在哪几条。**干完活没有文件，等于没干。**

**第二条：下一环只读文件，不靠聊天记录搬上下文。** 配图岗不问"这篇讲什么"，它去读写手留在目录里的正文；发行岗不问"审过了没有"，它去读审稿留下的结论文件。

立这两条，是因为我踩过两个坑。

**坑一，"两套账"。** 同一个事实，两处记的版本不一样：我印象里"这篇审过了"，状态文件里还写着"写作中"。哪个算数？说不清，因为两个都只是"我觉得"。唯一的解法是把真相源收敛到一处——状态文件说了算，印象不作数。

**坑二，"上下文丢失"。** 一环里费劲想通的东西，到下一环就不见了。下一环只能自己重新理解一遍，理解偏了，产出就偏了——而且偏得无声无息，因为没人知道原来那版长什么样。

**真正的瓶颈从来不是"写不写得出来"，是"东西怎么交到下一双手上"。** 手工时代这次交接靠脑子，工厂时代它靠物料随传送带走。我给这条线做的，就是把"脑子的交接"换成"物料的交接"。

## 二、它不是一条直线，是一张按品类分叉的图

五阶段铺开，看着像一条直线。跑起来才发现，它是一张图。

同一个入口，不同品类的选题走不同的阶段链：

| 品类 | 阶段链 | 特点 |
|------|--------|------|
| 技术长文 | 选题 → 写作 → 配图 → 审 → 发行 | 快 |
| 小红书 | 选题 → 写作 → 审 → 发行 | 最快 |
| 小说连载 | 选题 → 设定 → 结构 → 写作 → 审 → 运营 → 发行 → 商务 → 复盘 | 最长 |

技术长文要配图，所以"配图"在链上；小红书图多但结构简单，干脆把配图并进写作，链就短了；小说最重——动笔之前得先有世界观、人物、故事骨架，写完还得有人运营、有人发行、有人谈商务、有人复盘，一条链能拉出九个节点。

**跳过的阶段不触发。** 写小红书不会凭空多出一个"设定"环节，写技术长文也不会被逼着去做"商务"。

这更像一张地铁线路图，不像一条装配线。**装配线只能造一种东西；图能造很多种。** 区别在分叉发生在哪一刻——不是在线上临时拐弯，是**进门那一刻就分流**：选题先被判品类，判完直接进对应的那条链。

## 三、交接的是文件，不是聊天记录

这张图上每个节点都有一个固定角色，而且每个角色都被写死了两件事：**做什么、不做什么。**

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| 主编 | 判品类、定方向、出选题 | 不陷进具体写作 |
| 写手 | 写正文、定风格 | 不改选题方向 |
| 配图 | 出封面、出图、出图注 | 不改一个字正文 |
| 审稿 | 查结构、查合规、判过不过 | 不跳过审查硬发 |
| 运营 | 转化、传播、留存 | 不刷量、不追虚荣指标 |
| 发行 | 多平台发布 | 不改内容、不跳过发布检查 |
| 商务 | 会员、付费墙、产品化 | 不在平淡处砌墙 |
| 复盘官 | 复盘、提炼规则 | 不写流水账 |

"不做什么"这一栏，比"做什么"更值钱。**职责不清的团队，冲突都发生在边界上，不在能力上。**

交接也有硬规格。写手交给审稿，交的不是一句"写好了"，而是——**正文一篇（写清字数）+ 若干张配图位的图注 + 标题候选三条**。审稿接手就知道：该读多长的东西、该核几张图、该从三个标题里挑一个。

到配图这一环，分工还拆得更细：**封面自己出成品，复杂的机制图只出"出图提示词 + 草图"。** 原因很实在——内部那套出图工具，做简单卡还行，做复杂机制图效果不行，所以复杂图另换一个工具出终稿，这条线只负责把提示词和草图备好。**知道自己哪一段做不好、并把那一段主动交出去，是设计，不是示弱。**

## 四、真的跑通了一次

设计归设计，得看它真跑起来什么样。有两次值得记。

**一次是四平台全发。** 那篇把 125B 参数的大模型压进 16GB 内存的实测长文，最后同时出现在四个地方：公众号、知乎、社交平台的一条推文串、还有小红书（标题加七张 3:4 竖版图）。同一份正文，四个出口，各自适配。

**另一次留下了一条完整的五节点交接链。** 那是一篇讲推理框架怎么把 KV 缓存砍到四分之一的技术长文，从进线到发布包就绪，走完了五个节点：

**主编 → 写手 → 审稿 → 配图 → 公众号发布岗。**

链上最值得看的是**审稿打回了一次**。第一轮审稿判**不通过**——不是"感觉不行"，是列了具体条目：哪几个数字找不到一手出处，哪一句话把两段不同的时间说成了同一段。写手改完，第二轮才过。

**这条线不是"AI 一次就能写对"，是"AI 写错了，有人接得住"。** 一个不会打回的审稿环节，等于没有审稿环节。

## 五、然后它卡住了

现在讲最诚实的一段。

这条线能自己一路跑到"**发布包就绪**"——正文、封面、配图、排版稿、发布清单，全齐，一个包放在那里，就等最后一件事。

最后一件事是：**点发布。** 而这一步必须人按。这是红线，前面章节讲过：AI 可以写草稿，按发布键的必须是我。

结果就有账了：

- 有一篇试点稿，"就绪"之后**压了十天**没发出去。
- 有一个复盘事项，**逾期了六天**才补上。

十天，不是因为稿子有问题，也不是因为哪个环节慢了。是因为**所有发布动作都卡在同一个人身上**——那个人在忙别的，这个包就在那儿等着，状态一直停在"就绪"，谁也没法把它往前推一格。

这就是"**人工节点积压**"：流水线上有一站是单线程的，整条线的最快速度就被那一站锁死。

**卡住它的不是 AI 的产能，是"那个键只我会按"。**

我要说清楚：这不是故障，是设计。红线是故意的——发布的后果只有我能承担，所以那个键必须是我的。但**红线是有代价的，代价必须记账**，不能一边立红线一边假装它不要钱。这笔账，就是压在"就绪"状态里的那十天。

## 六、一次造假被抓

还有一次更严重的，不是慢，是假。

有一次全仓审计，在写手的一份产物里查出一条断言：**"这个账号已有某天的首篇发布记录"。** 审计员去核，那天**零发布**——所谓的"首篇记录"从来没有发生过。

关键在这里：**那句话不是人的笔误，是 agent 生成的。** 它是发行环节组装发布包时写下的，而且机制很朴素——它看见包名里带着那个日期、看见排期表里写着那个窗口，就顺手把"某天"写成了"某天已经发过"。**日期被当成了事件。**

处理方式是把候选断言一条条摊开核：一共**335 行**候选，核到最后拆成三堆——**111 条找到证据、22 条找不到证据、1 条被证伪。** 那 1 条就是它。

修法也是三条，都写死在流程里：

- **断言必须附证据。** 凡是"已发布 / 已完成 / 已登记"这类话，当场给出出处；给不出出处，就标"无一手证据，禁止引用"，不许当事实说。
- **日期不等于事件。** 文件名、排期、计划窗口，只能说明"它被创建或被计划过"，不能说明"它发生了"。
- **登记源优先。** 涉及发布状态的事实，只许去唯一的发布登记里读，禁止靠上下文猜。

**一个 agent 最危险的输出，不是它写错了字，是它把"计划"悄悄写成了"已完成"。** 前者你一眼看得见，后者它披着完成时态的外衣，混在真话里，能一路骗到最后。

## 七、状态机也会骗你

假话之外，还有一种是**结构性的失真**：没人撒谎，但表本身错了。

这条线最早的状态机，只有"文章级"的状态——一篇稿子是"写作中"还是"就绪"，一个字段。**它没有"平台"这个维度。**

于是就有这种事：一篇文章其实已经在一个平台上发出去了，状态文件里却还写着"就绪"。不是谁忘了改，是**那张表根本没有地方可以记"哪个平台发了"**。

修法是两刀：

- **第一刀，拆。** 把"发布"这个维度从状态机里**拆出去**，另立一个发布登记——状态机只管"稿子写到哪了"，发布登记只管"发到哪了、什么时候发的"。两个问题，两个真相源。
- **第二刀，加告警。** 加一条校验：**该有的记录没有，就报警。** 缺一条发布记录，不是安静地少一行，是跳出来喊。

**一张表想同时回答"稿子写到哪了"和"发出去了没有"，结果是两个都答不准。** 因为那本来就是两个问题，一个答案给不出两个。

## 尾声

回头看，这条线真正搭出来的，不是"AI 会写文章"。

会写文章，是它最不值钱的部分。

真正难的是**交接**：每一环把产出落成文件，下一环只读文件；角色写死"做什么、不做什么"；审稿该打回就打回；发现自己哪段做不好，就主动把它交出去。以及在一切都跑顺之后——**承认它卡在哪儿，还敢把那笔账写下来。**

这在七层模型里是**第五层，协作层**。这一层谈的不是单个 agent 有多能干（那是第四层的事），是多个 agent 怎么分工、怎么交接、怎么互相挑刺。它难，是因为它本质上是管理学问题，不是提示词技巧问题。**没对抗的协作，不是协作，是粉丝后援会。**

顺带说一句：这本书前面引到的那些文章，大多就是从这条线上流出来的。它们不是例子，是产出。

至于这条线的下一站——一个包全都齐了却没发出去，那笔账该怎么记、红线该怎么立，是后面单独一节的事。

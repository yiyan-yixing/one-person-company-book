## 这本书解决什么问题

这本书记录的是一个人用 AI 做事时真实发生的事：什么做成了、什么没做成、账上长什么样。它不提供一套「照着念就成」的方法，提供的是一份可以对照的过程记录。

读完你应当拿到三样东西。**怎么分工**：手上的活哪些能交给 AI、怎么把它们组织起来。**坑长什么样**：十几个策略全部被否、八次微调七次没过、素材备齐却最终没发出去、本地模型跑到一半被删掉，书里都写了当时是怎么判断的。**真实账本**：一家一人公司的钱和时间到底花在哪。

作者一个人运营着一家由 AI 员工组成的公司：写内容的、写代码的、做研究的、管账的、盯合规的，都是 agent。书里写的是这条路真实的样子，不回避失败。

全书 7 章 24 节，从「一个人干不过来」讲起，中间经过组织、真实任务链、本地算力、失败账本，最后落在钱和账：一个人的账到底怎么记。

## 适合谁读

- **想用 AI 做事、开公司的人**：独立开发者、自由职业者、做副业的人、小团队主理
- **已经在用 AI 工具、但卡在「怎么组织」的人**：想知道别人踩过哪些坑
- **对「一人公司」这件事好奇的人**：想知道一个人的边界到底能扩多大

> 假定你已经会用大模型类工具（知道什么是 API、什么是 agent），不解释基础名词。

## 不适合谁读

- **想学模型内部原理的读者**：那部分在同系列另一本《AI System 原理》，本书不涉及
- **想找一套可照抄模板的读者**：本书给的是具体判断与账本，不是操作手册
- **期待轻松读物的读者**：书里有失败复盘和账目数字，读起来不轻松

## 同步与红线

本站正文由主仓的同步脚本产出，推 `main` 后自动构建发布。同步前会跑一道红线闸。

**文本**：扫描所有将被提交的文件，命中内部仓库路径、凭据、金额、内部会议与白板引用等模式即**中止发布**。

**图片（已知盲区）**：图片的像素内容无法用文本 grep 检测。已实测发生过「正文文本干净、但配图 PNG 的像素里印着内部仓库路径」的情况。因此同步脚本会：

- 列出本批全部二进制文件并要求人工过目，未经确认不允许推送
- 用 OCR（`tesseract -l chi_sim+eng`）对图片自动扫描，命中内部路径模式即中止

OCR 有漏检可能（字体、小字号、艺术字、图形化排版都会降低识别率），**OCR 通过不等于图是干净的**——每张新图仍须人工过目一遍。

## 关于本站

静态站点由 MkDocs Material 构建，推 `main` 后自动发布到 GitHub Pages。本地预览：

```bash
pip install -r requirements.txt
mkdir -p .site-src/正文
cp -r manuscripts/. .site-src/正文/
cp archive/outlines/outline.md .site-src/目录大纲.md
cp index.md .site-src/index.md
cp -r assets .site-src/assets
mkdocs serve
```

正文按章分目录（`正文/第NN章-章名/`），章导语页是该目录下的 `index.md`；站点首页是封面页 `index.md`，由 `overrides/home.html` 渲染，数据来自 `mkdocs.yml` 的 `extra.*`。
